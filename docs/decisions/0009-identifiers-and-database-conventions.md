# ADR-0009: Identifiers and database conventions

- **Status:** Accepted
- **Date:** 2026-09-29

## Context
IDs appear in URLs and must not leak information or be guessable. The schema must evolve reproducibly.

## Decision
- **Primary keys are UUIDs**, generated by the application in a time-ordered form to keep index locality.
- **Flyway** owns the schema. Hibernate `ddl-auto` is `validate` (never `update` or `create`). Applied migrations are never edited.
- Naming: snake_case tables and columns, plural table names, explicit constraint names (`uq_...`, `fk_...`, `ck_...`).
- Important invariants are database constraints: NOT NULL, unique, foreign, check.
- Emails are unique case-insensitively (for example a unique index on `lower(email)`).
- Enumerated values are stored as text with check constraints.
- **Request reference numbers** (for example `REQ-000042`) are unique per organization, allocated from a per-organization counter updated atomically in the same transaction as the insert.
- Indexes are added only for named queries and documented in `docs/data-model.md`.
- Local seed data is loaded by a separate dev-only migration location or profile-guarded runner and never applies in deployed environments.

## Alternatives considered
- Auto-increment IDs: guessable and enumerable, and awkward across tenants.
- Random UUID v4 keys: hurt index locality on large tables.

## Consequences
Larger keys than integers, in exchange for safe exposure. The counter row can become a contention point per organization, which is acceptable for expected volumes.
